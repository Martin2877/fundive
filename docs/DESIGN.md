# FunDive 画面与体验设计

> 目标：玩家一进水就“相信这是水下洞穴”——看得清该看的、看不清该怕的，且每个位置的所见与所操作互相呼应。

## 1. 设计原则

1. **光是主角**：洞里没有环境光，视野 = 潜水灯 + 天窗。亮度、阴影、微粒都从这一点推导。
2. **能见度是玩法**：雾、泥沙、灯束共同决定“能看多远”，它直接关联迷路/泥沙结局，不是装饰。
3. **所见即所碰**：网格放样与碰撞共用同一个 `wallRadius()`，玩家贴墙时不穿模、不隔空撞。
4. **确定性**：同一 (mapId, seed) 在所有客户端生成同一世界；画质档位只改“精细度”，不改“布局”（gap/物件个数由种子决定，不随档位变化）。
5. **每个改动都能被截图验收**：见第 7 节。

## 2. 渲染管线（`client/src/engine/`）

```
场景(PBR 洞壁 + 钙质 + 残骸 + 生物)
  └─ VolumetricPass   自带 MSAA RT + 深度纹理；沿视线 22 步进，累积 灯锥/天窗光柱 散射（被洞壁深度截断）
  └─ UnrealBloom      阈值 0.92，只让灯斑/高光晕开
  └─ OutputPass       ACES 色调映射
  └─ UnderwaterPass   面镜椭圆暗角 + 鼻梁压暗、轻微色散、暗部青/亮部暖、胶片颗粒、氮醉/惊慌扭曲
```

| 模块 | 文件 | 职责 |
|---|---|---|
| 洞穴放样 | `cave.js` | 脊线→管状网格（平整沉积地面、扇贝纹、天窗收口）、钙质柱体、崩塌巨石、引绳、导航场 |
| 程序贴图 | `texgen.js` | 无缝周期噪声生成 岩石/沙底 的 albedo + 法线 + 粗糙度（无外部素材） |
| 洞壁材质 | `materials.js` | 三平面映射（无拉伸/无接缝）、双尺度混合去重复、法线朝上处混入沙底、天窗焦散；**全局水下分通道雾** |
| 水体 | `water.js` | 随深度/天窗变化的环境光与雾色、GPU 端循环的“海雪”（只在灯束内发亮）、气泡、斯涅尔窗水面 |
| 灯 | `lamp.js` | 手持偏置聚光灯（带阴影→视差立体感）+ 宽角溢光 + 近身补光；低画质回退为锥体网格 |
| 体积光 | `volumetric.js` | 灯束与天窗光柱的丁达尔散射；泥沙浓度提升散射系数 |
| 后期 | `postfx.js` | 合成链与水下调色 |
| 画质 | `quality.js` | low / mid / high 三档，持久化 |

### 水下雾（能见度的物理基础）
Beer–Lambert：`T = exp(-density · (1.55, 1.0, 0.78) · distance)`，红光衰减最快，远处自然偏青蓝。`density = 2 / vis`（`vis` 取自地图 `water.vis` × 宇宙修饰）。泥沙浓度 `siltD` 使 density × `(1 + 4·siltD)`，氮醉再加成。

### 环境光
`k = max(exp(-depth/14), 天窗接近度)`，下限 0.12。水面附近明亮、下潜十几米后几乎全黑，只剩天窗周围一层蓝光；雾色同步变暗，远景与背景同色无接缝。

## 4. 游戏全流程与每一步的所见/所做

| 阶段 | 玩家看到 | 玩家做什么 | 设计要点 |
|---|---|---|---|
| 菜单 | 所选地图洞穴的缓慢巡游（带灯），面板半透明 | 选图/换宇宙/组队 | 背景即预览，选图立刻换景；巡游速度 1.4m/s 不晕 |
| 计划 | 面板 | 设气量/折返气量 | 与画面无关，保持安静 |
| 入水 | 头顶亮蓝水面（斯涅尔窗，波纹+闪光），朝向自动对准洞内 10m 处脊线；竖井图会低头看向深渊 | 点击锁定鼠标，WASD | 首帧给出“要去哪”的视觉锚点；出生略低头 |
| 日光带（入口/天窗） | 明亮蓝绿水体、光柱、洞壁焦散、藻绿 | 熟悉操作、调中性浮力 | 环境光高，丁达尔光柱明显；这里是“最后的安全感” |
| 过渡带 | 光线迅速收束，灯束开始成为主光源 | 开灯、抓引绳 | 环境光随深度指数衰减，玩家会本能地去开灯/找绳 |
| 暗区主通道 | 灯斑内湿润岩壁（粗糙度低→有高光）、沙底波纹、钟乳石投影随手持灯位移 | 沿引绳游动、拍照 | 手持偏置灯使阴影有视差；光斑外全黑，只有微粒在束里闪 |
| 厅/大空间 | 灯束照不到远壁，雾色吞没远景 | 靠引绳定位 | 刻意不可见全貌：大空间的恐惧来自“看不到边” |
| 窄缝 | 墙面逼近、钟乳石/巨石在灯下变形 | 小幅度游动，避免踢水 | 碰撞与墙体一致；近墙时法线细节清晰 |
| 泥沙区 | 灯束变成实体光柱，雾密度 ×(1+4·siltD) | 停下、抓线、等待 | 泥沙既是视觉也是结局风险 |
| 深区/氮醉 | 色散、画面扭曲、紫色暗角、幻觉光源 | 看深度表、折返 | 后期通道承担全部“精神状态”表现 |
| 出口 | 水面光窗由远及近 | 缓慢上升、安全停留 | 回到日光带，亮度回升作为“得救”的情绪回报 |
| 结算 | 结局文案 + 照片 | 重试/换宇宙 | |

### 操作手感参数（`session.js`）
- 视野：竖直 FOV 75°，速度越快最多 +5°；取景器 42°。
- 相机：呼吸起伏 0.004rad、踢水节奏 0.006rad、横移倾斜 0.02rad/(m/s)；氮醉/惊慌叠加摇晃。
- 灯：手持偏置（右 0.2 / 下 0.16 / 前 0.15），主灯 110cd、溢光 22cd；备用灯 45% 亮度；故障时簇状眨停（sputter，非逐帧频闪）。

## 6. 性能预算（高档，1280×720，M 系列 GPU）
目标 ≥ 60fps；单场景 draw call < 120、三角形 < 150k、纹理 < 40。`npm run shots` 同时给出帧率门禁（> 30fps）。

## 7. 开发与验收流程

1. **改动前**：`npm run dev`，保持开发服务器运行。
2. **逻辑回归**：`npm test`（世界生成 + 碰撞一致性 + 联机冒烟）。
3. **画面验收**：`npm run shots`（可加 `-- --maps=0,2 --quality=mid`）。对每张地图的 4 个检查点（出生/前段/中段/深处）：
   - 截图落在 `reports/shots/`，人工看图；
   - 自动门禁：平均亮度 0.03–0.6、过曝像素 < 30%、帧率 > 30、控制台零错误。
4. **三档画质都要过**：low / mid / high 各跑一遍（low 走无后期回退路径）。
5. **提交前**：`npm run build` 通过。
