# FunDive 玩法与流程设计（问题3）

> 对应 `_dev.md`「问题3」。本文档是**设计规划**，分期实施前请确认方向。
> 已完成：HUD 顶部「目标行 / 罗盘 / 区域名」改为 `#topc` 纵向 flex 堆叠，不再互相遮挡。

## 0. 现状诊断

| 反馈 | 根因（代码定位） |
|---|---|
| 指南针与目标遮挡 | `#obj` 固定 top:18px 且最多 4 行（目标+附加挑战），`#cmp`/`#region` 写死 top:52/80px → **已修** |
| 地图重复性高 | 海图全部是「潜水船→锚点→一串等距点名站」；三艘沉船（wreck/yongala/thistlegorm）共用同一个 `wreckBoxes()` 布局与完全相同的 `ref:'wreck'` 节点坐标 |
| 目标太小、宇宙间差异弱 | `makeUniverse` 只抽 1 个主目标，且恒定位于路线最后 1~2 个节点；bonus 挑战只是附加清单 |
| 下水不知道做什么/往哪走 | 引导 = 顶部一行目标文字 + 罗盘 ◆ 指最终点；STORY beats 只在 3 个固定节点触发；没有「当前该去哪」的过程引导 |
| 引导一刀切 | 新手和老手看到同样的提示密度；账号已有 dives/课程数据但没用于调节引导 |
| 奖惩单薄 | 好结局记章节✓+综合分；坏结局只记结局图鉴。没有表现评级、没有解锁递进 |

## 1. 设计目标

1. **下水即有动线**：任何一潜都有清晰的「推荐游玩路径」——先去哪、看什么、目标在哪、怎么回来。
2. **地图即角色**：每张图有自己的空间结构与专属玩法（沉船按真实船体设计）。
3. **引导按需供给**：账号经验决定提示密度，玩家可手动覆盖。
4. **每潜有评价**：结算给评级与教训，奖励看得见、惩罚讲得清。

## 2. 流程引导系统「潜导」（核心，P1）

### 2.1 航段（waypoint）机制

把 `map.route` 的具名节点组织成航段序列。`uni` 生成时按主目标类型组装「计划动线」：

```
uni.plan = [
  { node: 2, kind: 'leg',   text: '下到锚点，沿绳前进' },
  { node: 5, kind: 'leg',   text: '穿过窄缝' },
  { node: 9, kind: 'obj',   text: '货舱打捞点' },
  { node: 0, kind: 'exit',  text: '原路回锚绳，放浮标' },
]
```

- HUD 目标行下方/罗盘 ◆ 始终指向**当前航段**（不再是只有最终点）：`下一站 · 海葵田 62m`。
- 到点（复用 region 检测，< r+2.5m）自动推进，talk 播报一句该航段的解说（数据放 `map.legs[]` 或复用 STORY.beats 扩充）。
- 完成当前航段后亮出下一段；`survey`/`census` 天然多航段。
- 计划动线在**潜点详情页**展示为路线摘要（手绘地图已有 `ui/survey.js`，把航段编号标上去）。

### 2.2 潜导解说（talk）

每航段一句「潜导在耳边」式的提示，承担三件事：方向（"岔口走左"）、风险（"这里流大，贴右壁"）、风味（剧情）。数据来源：扩展 `STORY[mapId].beats`，每条 beat 增加 `guide` 字段，按玩家引导等级播报（见 §5）。

### 2.3 迷失补救

- 偏离当前航段 >X 米且未朝目标移动 N 秒 → 潜导提示"偏航了，回到引绳"。
- navReq 图：偏航惩罚照旧（罗盘是唯一导航），但新手模式下允许一次"潜导指引"（临时亮出返回方位 10s）。

## 3. 目标体系升级（P2）

### 3.1 目标分级

- **主线目标**（必做，1 个）：影响结局评级。不再恒定在末段——由 `map.legs` 声明候选区段，宇宙种子在候选中抽取，位置可前可后、可在支洞。
- **图特目标**（地图绑定，0~1 个）：每张图一个绑定身份的玩法（见 §4 表）。例：蓝角=挂钩观鲨计时、睡美人=分段救援。
- **宇宙支线**（现有 sides/bonus 保留）。

### 3.2 多阶段任务链

把现有"到点即完成"的单点目标升级为 2~3 阶段链，让地图的"大"有意义：

- `rescue`：发现踪迹（装备/气泡声 talk）→ 循迹到支洞气室 → 挂拖带 → 慢速带回（拖带时限速已有）。
- `salvage`：找到散落线索（2 处发光点）→ 定位主物 → 负重回程（重量影响浮力已有）。
- `explore`→「巡线+到达」复合：不再只是摸一块石头，沿途要确认 N 个检查点（复用 survey 的 legs 渲染）。
- `photo`：指定物种 + **指定生境**（"在海狼风暴区拍"），位置由航段绑定，避免"随便拍到就完事"。

新目标类型（复用现有机制，成本低）：

| 类型 | 玩法 | 依赖 |
|---|---|---|
| `trail` 循迹 | 沿 N 个线索点逐步逼近目标 | objective.js legs 模式 |
| `line` 布线 | 在指定支洞铺一段引绳（需线轮装备） | hasReel/G 键机制 |
| `signal` 信标 | 到远端旱厅发信标呼救 | 已有 rescue_call 结局路径 |
| `survey2` 测深 | 在 3 个指定深度带各停留 10s | depthTarget 机制（教学已用） |

### 3.3 「大目标」呈现

- 目标物视觉分级：主目标给更强的光柱/标记（现有 cookie+glow 放大），远处即可见；
- HUD 目标行显示阶段进度 `②/④`；罗盘 ◆ 永远指当前阶段位置。

## 4. 地图差异化（P3）

### 4.1 沉船：按真实船体重建

`wreckBoxes()` 目前为所有沉船生成同一艘 36m 箱船。改为**数据驱动**：`map.ocean.wreck` 增加 `layout` 字段，描述甲板分段、舱室、桅杆、倾角；碰撞与网格仍走 AABB 拼装（成本低、确定性保持）。

| 图 | 真实原型 | 差异化设计 |
|---|---|---|
| wreck 海鹞号 | 小型沿岸货船（~35m） | 保持短小：单货舱+小舰桥，进舱只有一个口——教学型沉船 |
| yongala 永加拉号 | 110m 客轮，侧卧倾覆 | **侧躺姿态**（roll ~60°）：甲板面变成斜墙、舱口朝天开、穿行路线变成"沿斜面爬升"；烟囱倒在沙地上单独成景；强流外海 |
| thistlegorm 蓟马号 | 126m 军需货轮， upright | **双货舱贯穿**：1号舱卡车/摩托/弹药箱阵列（已有 props 放大成列）；船尾断裂段单独一块、高射炮矗立；舰桥多层（海图室→舰桥→桅杆瞭望）垂直动线 |

配套：route 节点重排（锚绳落点、穿行顺序不同）；STORY beats 节点下标同步更新；`ocean.js` 读 `wreck.layout`（无则回落通用布局）。

### 4.2 海图结构差异化

现所有海图共享「船→锚→等距折线」骨架。引入 3 种路线形态（`map.ocean.shape`）：

- `line` 现行折线（礁坡/断崖漂流适用）
- `loop` 环礁巡游：起点=终点都在锚绳附近，路线绕礁丘一圈（rajaampat/ariatoll 适用——"逛花园"）
- `hub` 中心放射：锚点居中，多个兴趣点扇形分布，潜导按目标推荐顺序（reef 适用）
- 地形特征复用现有 wall/pit/kelp/berg，追加 `bommie`（孤立礁丘群）与 `sand`（大沙地+残骸点）

## 5. 账号分级引导（P4）

### 5.1 经验评级

从 `store.data` 推导 `diverLevel`（不新增存档字段，纯函数）：

```
dives<6 或 课程 ow 未完成        → L0 学员
dives≥6 且 (aow 完成 或 好结局≥5) → L1 潜水员
dives≥15 且 高难图(难度≥4)通关≥2  → L2 老手
```

### 5.2 引导档位（settings.guide：auto/full/lite/off）

| 档位 | 航段播报 | 潜导解说 | 风险预警 | 罗盘 |
|---|---|---|---|---|
| auto→L0 | 每段到点/偏航必报 | 全量 guide 文案 | 折返气/深度/流速主动提醒 | 常显 |
| auto→L1 | 只报航段名+距离 | 只报风险类 | 只报折返气 | 常显 |
| auto→L2 | 仅 HUD 一行 | 不报 | 不报 | 常显 |
| lite/off | 同 L2 / 全关 | — | — | 按装备 |

默认 auto；菜单设置页可改（存 `settings.guide`，随账号上云）。

## 6. 奖惩机制（P5）

### 6.1 潜水评级（结算）

按 `result.stats` 已有数据评 S/A/B/C：

- 目标完成（必要前提，否则最高 B）
- 余气 ≥折返+30 / 超时 / 上升违规次数 / 搅沙次数 / 惊慌峰值 / 附加挑战完成数

结算页大号评级章 + 一句点评；评级进 `store.chapters[mapId].grade`（地图卡显示 ★→S/A/B/C 替换现有✓）。

### 6.2 难度资历建议（不做锁定）

- 难度≥4 的图：玩家没有前置难度图的好结局、对应课系也没满 6 星时，潜点详情页给一句资历建议（"建议先通关 ★★★ 潜点或修完 XX 课程"）——不锁图，玩家说了算。
- 高评级回报：S 评图解锁该图专属支线机缘「完美者印记」（uni.sides 确定性生成、联机一致，拾取按本机 S 评判定）；综合分公式把评级计入（潜水×2 → 潜水×2+评级加成 B1/A2/S4）。

### 6.3 惩罚讲清楚

坏结局结算页已有 hint——补一行"这次差在哪"（从 stats 归因：气耗型/深度型/泥沙型/惊慌型），并给出对应课程课节链接（"去练：中性浮力"点击跳课程表）。

## 7. 分期实施计划

| 期 | 内容 | 验收 |
|---|---|---|
| P1 潜导 | uni.plan 航段 + HUD 航段行 + 罗盘指当前段 + 偏航提示 + map.legs 数据 | 每张图下水跟着 ◆ 能走完全程不迷路；worldtest 加 plan 校验 |
| P2 目标 | 任务链（trail/rescue 分段）、map 候选目标区、目标阶段 HUD | 同一图两个宇宙目标位置/玩法不同；oceantest 同步 |
| P3 沉船 | wreck.layout 数据化 + 三船重建 + 节点/剧情同步 | shots 三船截图差异肉眼可辨；oceantest 过 |
| P4 分级 | diverLevel + settings.guide + 提示密度接入 | 新档/老档各开一潜对比提示量 |
| P5 奖惩 | 评级章 + 资历建议 + 结算归因 + 完美者印记 | 结算页显示评级；高难图详情页有建议文案；S 评后印记可收集 |

依赖顺序：P1→P2（航段是任务链的骨架）→P3 可并行；P4/P5 独立。

## 8. 不做 / 缓做

- 不重做碰撞体系（AABB 沉船已够用）；不引外部素材（保持程序化生成的确定性优势）。
- 洞穴图结构暂不重排——genSideBranches 已提供宇宙间差异；先补引导与目标，再看是否需要更大洞穴。
